# OneThing 模式重构设计方案

> 版本：v2.0 | 模块：任务流 (Task Flow) → OneThing | 依据：项目需求.md

---

## 1. 核心理念重新定义

### 1.1 现有问题

- 当前任务流是"待办事项池"，任务混杂在一起
- 缺乏优先级和聚焦机制
- 任务可能太多太杂，无法专注

### 1.2 OneThing 理念

> **Slogan**: One thing at a time. 一次只专注一件事。

| 概念 | 定义 | 性质 |
|------|------|------|
| **OneThing 项目** | 一个中长期专注领域，如"研发小程序"、"带女儿学英语" | 容器/项目 |
| **OneThing 队列** | 当前正在专注的 1-3 个项目 | 焦点列表 |
| **项目阶段** | 项目下的分类阶段，如"阶段一"、"P2阶段" | 任务分组 |
| **项目待办** | 阶段下的具体待办事项 | 任务项 |

### 1.3 核心流程

```
┌─────────────────────────────────────────────────────────┐
│                    OneThing 队列                         │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐    │
│  │ 🎯 研发小程序 │  │ 📚 学习 SwiftUI │  │ 👧 带女儿学英语 │   │
│  │   3 待办    │  │   5 待办    │  │   2 待办    │    │
│  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘    │
└─────────┼────────────────┼────────────────┼────────────┘
          │                │                │
          ▼                ▼                ▼
    ┌───────────┐   ┌───────────┐   ┌───────────┐
    │ 项目详情   │   │ 项目详情   │   │ 项目详情   │
    │ ├─ 阶段一  │   │ ├─ 日常任务 │   │ └─ 今日任务 │
    │ │  ├─待办1 │   │ └─ 阶段一  │   └───────────┘
    │ │  └─待办2 │   │    └─待办1 │
    │ └─ 阶段二  │   └───────────┘
    │    └─待办1 │
    └───────────┘
```

## 2. 数据模型设计

### 2.1 新增实体

#### OneThingProject (项目)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 唯一标识 |
| name | String | 项目名称 |
| icon | String | Emoji 图标 |
| color | String | 主题色 (Hex) |
| description | String? | 项目描述 |
| status | ProjectStatus | 状态：active / completed / archived |
| isInQueue | Bool | 是否在 OneThing 队列中 |
| queueOrder | Int | 队列中的顺序 |
| createdAt | Date | 创建时间 |
| updatedAt | Date | 更新时间 |

#### ProjectStage (项目阶段)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 唯一标识 |
| projectId | UUID | 所属项目 |
| name | String | 阶段名称，如"阶段一"、"P2内容" |
| type | StageType | 阶段类型：general / daily / weekly / milestone |
| sortOrder | Int | 排序 |
| createdAt | Date | 创建时间 |

#### ProjectTodo (项目待办)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 唯一标识 |
| projectId | UUID | 所属项目 |
| stageId | UUID? | 所属阶段（可为nil） |
| title | String | 待办标题 |
| content | String? | 详细描述 |
| status | TodoStatus | 状态：pending / completed |
| priority | Priority | 优先级：high / medium / low |
| recurrence | Recurrence? | 重复规则：daily / weekly |
| dueDate | Date? | 截止日期 |
| completedAt | Date? | 完成时间 |
| sortOrder | Int | 排序 |
| createdAt | Date | 创建时间 |
| updatedAt | Date | 更新时间 |

### 2.2 关系设计

```
OneThingProject 1:N ProjectStage
OneThingProject 1:N ProjectTodo
ProjectTodo N:N Tag
ProjectTodo N:N Entity
```

### 2.3 枚举定义

```swift
enum ProjectStatus: String, Codable {
    case active    // 进行中
    case completed // 已完成
    case archived  // 已归档
}

enum StageType: String, Codable {
    case general   // 一般阶段
    case daily    // 每日任务
    case weekly   // 周常任务
    case milestone // 里程碑/长期目标
}

enum TodoStatus: String, Codable {
    case pending   // 待处理
    case completed // 已完成
}

enum Priority: String, Codable {
    case high
    case medium
    case low
}

enum Recurrence: String, Codable {
    case daily   // 每日
    case weekly  // 每周
}
```

### 3.3 阶段类型说明

| 类型 | 图标 | 说明 | 位置 |
|------|------|------|------|
| **每日任务** | 📅 | 每天重复的任务，如"打卡"、"日常" | 详情页顶部 |
| **周常任务** | 📆 | 每周重复的任务，如"周副本"、"周常" | 详情页顶部 |
| **里程碑** | 🏆 | 长期目标/成就，如"获取坐骑"、"完成某个大版本" | 详情页中上部 |
| **阶段目标** | 📋 | 一般阶段，如"P1阶段"、"基础架构" | 详情页中部，可下拉添加多个 |
| **一般任务** | ⬜ | 普通待办 | 各阶段内 |

## 4. 队列管理逻辑

### 4.1 队列规则

| 规则 | 说明 |
|------|------|
| 最大数量 | 最多 3 个进行中项目 |
| 新增逻辑 | 新建项目时询问是否加入队列 |
| 退出队列 | 项目完成后自动移出队列，可手动归档 |
| 切换焦点 | 拖拽调整顺序，第一位为当前焦点 |

### 4.2 项目生命周期

```
创建 ──→ 进行中 ──→ 已完成 ──→ 已归档
  │          │
  │          └────── 队列中 (最多3个)
  │
  └────────────── 可选加入队列
```

### 4.3 与原任务流的关系

| 场景 | 处理方式 |
|------|----------|
| 迁移现有任务 | 可将原任务流 Item 转为项目待办 |
| 临时任务 | 仍保留在原任务流，不进入 OneThing |
| 项目相关任务 | 从项目详情页创建，自动关联项目 |
