## 💡 项目愿景 (Vision)

开发一款极简的**Apple原生任务与人生记录应用 (iOS & macOS)**，核心理念是将待办事项、生活点滴、知识积累以**队列 (Queue) + 时间轴 (Timeline)** 的形式呈现。

采用 **"Sidebar + Flow"** 的导航模式，左侧管理领域与分类，右侧展示流动的时间线。利用 iCloud 保证数据绝对隐私与安全，既能抵制多任务处理的诱惑，又能记录人生的精彩瞬间与知识足迹。

### 🎯 核心理念

**以任务驱动一切 Flow**：
- 每天要做的任何事情都是任务（吃饭、开车、开会、陪娃、做饭等）
- 核心主线是 **Task Flow**，严格按时间线推进
- 新建 Task Flow Item 时，可选择默认加入 Schedule Flow（默认开启）

### 🔄 三大核心 Flow

| Flow | 定义 | 定位 |
|------|------|------|
| **Task Flow** | 任务执行主队列 | 串行推进，专注当下 |
| **Schedule Flow** | 日程流水账 | 日常记录，形成自然日记感 |
| **Event Flow** | 人生重大事件 | 里程碑：买房、升职、就医、购置大件等 |

### 📌 自定义 Flow (SubFlow)

从 Task/Life/Event 中选定主题，生成可持续跟踪的子 Flow：
- 典型场景：春节旅行、某次出差、购车过程、健康恢复计划
- 生命周期：Pin（创建）→ 跟踪中 → Unpin（完结，保留历史）

### 🖼️ UI 风格示意

- 所有 Flow 采用统一的简洁风格
- 同一天日期合并展示
- Item 内容支持 `#标签` 和 `@对象`（人物、实体）

## 🎯 核心功能需求 (Core Features)

### 1. 导航与布局 (Navigation & Layout) —— "The Frame"

> 核心交互：采用 `NavigationSplitView` (Sidebar + Detail) 结构，适配 iPad/Mac 大屏及 iPhone 侧滑菜单。

#### 左侧边栏 (Sidebar)

| 分区 | 内容 |
|------|------|
| **Flows** | ✅ 任务流 / 📅 日程流 / 📅 事件流 / 自定义Flow |
| **Domains** | 💼 工作 / 🏠 家庭 / 🏥 健康 / 🌱 成长 ... (支持自定义) |
| **People** | 👧 大女儿(12) / 👶 二女儿(5) / 👨 老爸(3) / 👩 老婆(8) ... (自动聚合记录数) |
| **Tags** | #电影 #阅读 #历史 #新闻 #人物 ... |

#### 右侧内容区 (Content Flow)
- 展示当前选中视图对应的 **Timeline Flow**
- 所有的Flow页面都是同一种样式，垂直排列的时间线，Item列表：每个Item占一行，左边是一个圆形数字（日期），右边是事件描述。如果是同一天的则合并时间线，不需要每个Item左边都要有圆形数字（日期），仅针对每天最新的一条Item，Item列表是按时间倒序的，如果是任务流，则Item左边会有Checkbox，其他Flow不显示，这个Timeline上要清晰的显示年、月、日的列表，当滑动到月的时候，月这个标题会被固定在顶部，下面继续滑动的是日的

### 2. 任务流 (Task Flow) —— "The Queue"

> 场景：工作、执行、Getting Things Done。 参考：Workflowy APP的思路

- 任务流是唯一的"执行主队列"，按`计划时间`排序，强调**串行推进**
- 新建 Task Item 时，默认同步生成一条 Schedule Flow 记录（可手动关闭）
- 不需要弹出新增页面，点击创建按钮，会直接在列表第一条创建一个记录，并且直接进入编辑状态，可以输入内容
- 支持快速输入：`写周报 #工作 @老板`
- 支持从任务一键"转事件"（当任务具有里程碑意义时）
- `#符号`表示标签，`@符号`表示对象
- 当输入`#符号`时候，会自动关联历史标签，比如#工作，如果输入一个工字的时候，会过滤工作标签，@对象也是同样的道理，并且标签和对象都会自动标记色块，并且色块和标签是一一对应的，永久存储起来，下一次输入#工作的时候，和之前的色块是一致的

### 3. 日程流 (Schedule Flow) —— "The Traces"

- **核心定义**：日程流是"日常流水账"，可来自任务自动同步或手动记录。同一天按日期分组展示，保留时间顺序，形成自然日记感。

- **关键动作**：
  - 标记为"值得纪念"后推送到 Event Flow
  - 通过 `#标签` 和 `@对象` 自动建立索引关系

### 4. 自定义 Flow (Pinned SubFlow) —— "The Trackers"

- **核心定义**：从 Task/Life/Event 中选定一个主题，生成可持续跟踪的子 Flow
- **典型场景**：春节旅行、某次出差、购车过程、健康恢复计划
- **生命周期**：Pin（创建）→ 跟踪中 → Unpin（完结，可保留历史）
- **聚合规则**：子 Flow 自动聚合相关 Item（手动添加 + 智能推荐），仍保持原始 Item 所属主 Flow 不变，避免数据复制

### 5. 事件流 (Event Flow) —— "The Highlights"

> 场景：人生里程碑，大事记。

- **核心定义**：事件流是"高价值节点库"，记录对人生有长期意义的事项

- **入流方式**：
  - 从 Life/Task 一键升级为 Event
  - 直接创建 Event（如买房、升职、就医、购置大件设备）

- **展示方式**：年/月时间轴聚合

## 🏗️ 架构与技术方案 (Tech Stack)

### 1. 技术选型 (Apple Native)

| 技术 | 说明 |
|------|------|
| **开发语言** | Swift 5.x |
| **UI 框架** | SwiftUI，采用 `NavigationSplitView` 实现 Sidebar 布局 |
| **平台适配** | iOS (Tab/Sidebar 混合) 和 macOS (标准三栏/两栏布局) |
| **数据存储** | SwiftData + H2/MySQL |
| **数据同步** | ~~CloudKit (iCloud)~~ → 自建后端同步 |
| **后端服务** | Spring Boot 2.7.18 + JWT 认证 |

### 2. 数据模型设计 (SwiftData Model)

#### 枚举与实体

| 模型 | 类型 | 字段 |
|------|------|------|
| **FlowType** | Enum | `task` / `life` / `event` / `custom` |
| **Flow** | Entity | `id`, `name`, `type`, `icon`, `color`, `isPinned`, `sortOrder`, `createdAt` |
| **FlowItem** | Entity | `id`, `flowId`, `title`, `content`, `occurredAt`, `endAt`, `status`, `priority`, `domainId?`, `isFromTaskSync`, `sourceItemId?`, `createdAt`, `updatedAt` |
| **Domain** | Entity | `id`, `name`, `icon`, `sortOrder` |
| **Tag** | Entity | `id`, `name`, `color` |
| **Entity** (@对象) | Entity | `id`, `name`, `type(person/device/car/house/other)`, `note` |

#### 关系设计

| 关系 | 说明 |
|------|------|
| Flow 1:N FlowItem | 每个 Flow 包含多个 Item |
| FlowItem N:N Tag | 通过中间表 `FlowItemTag` |
| FlowItem N:N Entity | 通过中间表 `FlowItemEntity` |
| FlowItem N:1 Domain | 每个 Item 属于一个领域 |
| FlowItem 1:0..1 SourceItem | 任务→日程流、升级事件的追溯链 |

#### 智能解析规则

- 输入框实时解析 `#标签` 与 `@对象`
- 不存在时自动创建（可配置为"仅建议不自动创建"）

### 3. 页面架构 (Page Structure)

| 组件 | 说明 |
|------|------|
| **SidebarView** | Flows、Domains、People、Tags 四大分区 |
| **TimelineListView** | 按天分组的时间线列表（当天合并显示） |
| **ItemComposerView** | 快速输入 + 结构化字段编辑 |
| **ItemDetailView** | 详情、关联关系、转流操作 |
| **SearchView** | 按关键词/标签/对象全局检索 |

#### 状态管理
- `AppState`: 当前选中的导航节点、过滤条件、搜索词
- `FlowFilter`: 时间范围、领域、标签、对象、状态

#### 跨平台适配
- **iPhone**: Tab + NavigationStack（Flow 列表与详情层级推进）
- **iPad/macOS**: NavigationSplitView（Sidebar + Content + Detail）

#### 关键组件
- TimelineDaySection、FlowItemRow、QuickInputBar、TagChip、EntityChip

#### 💻 macOS/iPad 布局

| 层级 | 说明 |
|------|------|
| **Sidebar** | 导航菜单 (All, Flows, Domains, Tags) |
| **Content List** | 中间栏，展示选中分类下的 Item 列表 (Timeline) |
| **Detail** | (可选) 右侧栏，展示选中 Item 的详细信息/笔记 |

## 🌐 后端服务架构 (Backend Architecture)

### 1. 为什么需要自建后端

- iCloud/CloudKit 在中国大陆地区不稳定
- 数据完全自主可控
- 支持多设备同步（Android/Web 扩展）

### 2. 技术选型

| 组件 | 说明 |
|------|------|
| **后端框架** | Spring Boot 2.7.18 |
| **Java 版本** | Java 11 |
| **数据库** | MySQL 8.0+ / H2 (测试) |
| **认证** | JWT (jjwt 0.11.5) |
| **API 文档** | Swagger / OpenAPI |

### 3. API 设计

| 模块 | 接口 | 认证 |
|------|------|------|
| 认证 | /api/v1/auth/login, /register, /refresh | 公开 |
| Flow | /api/v1/flows/* | JWT |
| FlowItem | /api/v1/flow-items/* | JWT |
| Domain | /api/v1/domains/* | JWT |
| Tag | /api/v1/tags/* | JWT |
| 同步 | /api/v1/sync, /sync/full | JWT |

### 4. 数据同步策略

- **本地优先 (Local-First)**：所有操作先写本地 SwiftData
- **增量同步**：基于 `updatedAt` 字段做增量拉取
- **冲突处理**：本地数据优先，按时间戳合并

## 🎨 UI/UX 设计原则

| 原则 | 说明 |
|------|------|
| **时间优先** | 所有 Flow 都遵循同一时间轴视觉语言，减少学习成本 |
| **轻量录入** | 新增入口始终可达（快捷键 / 浮动按钮 / 顶部输入栏） |
| **结构化但不僵硬** | 先自然语言输入，再自动解析为标签、对象、领域 |
| **日维度聚合** | 同一天记录合并展示，避免碎片化视觉噪音 |
| **渐进增强** | MVP 先文本与关系，照片、导出、统计后续再加 |
