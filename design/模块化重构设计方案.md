# TigerFlow 模块化重构设计方案

> 版本：v2.1 | 生成日期：2026-03-10 | 目的：三大 Flow 模块解耦

---

## 1. 背景与问题

### 1.1 当前问题

当前代码中，**任务流、日程流、事件流** 共用以下文件：

| 文件 | 共用程度 | 问题 |
|------|----------|------|
| TimelineListView.swift | 80% 共用 | 大量 `if flowType == .task` 判断混杂 |
| TimelineView.swift | 90% 共用 | 列表逻辑与具体 Flow 耦合 |
| TimelineItemView.swift | 85% 共用 | 通过参数区分不同 Flow 行为 |
| TaskEditorView.swift | 70% 共用 | UI 组件与业务逻辑混合 |

### 1.2 重构目标

1. **独立性**：各 Flow 模块完全独立，改动互不影响
2. **可维护性**：代码清晰，易于理解和修改
3. **可扩展性**：添加新 Flow 只需实现协议
4. **可测试性**：单元测试更简单

## 3. 核心协议设计

### 3.1 FlowModule 协议

```swift
import SwiftUI
import SwiftData

/// Flow 模块协议 - 定义各 Flow 的行为规范
protocol FlowModule: Identifiable {
    /// Flow 类型
    var flowType: FlowType { get }

    /// 显示名称
    var displayName: String { get }

    /// 图标
    var icon: String { get }

    /// 是否显示 Checkbox（仅任务流）
    var showCheckbox: Bool { get }

    /// 是否显示时间（日程流、事件流）
    var showTime: Bool { get }

    /// 是否支持子任务（仅任务流）
    var supportsSubtasks: Bool { get }

    /// 是否支持拖拽排序
    var supportsDragReorder: Bool { get }

    /// 数据过滤：根据 FlowType 过滤 Items
    func filterItems(_ items: [FlowItem]) -> [FlowItem]

    /// 创建 Item
    func createItem(
        title: String,
        content: String?,
        occurredAt: Date,
        tags: [Tag],
        entities: [Entity],
        modelContext: ModelContext
    ) -> FlowItem

    /// 切换完成状态
    func toggleComplete(_ item: FlowItem)

    /// 是否可以完成（某些 Flow 可能不允许）
    var canComplete: Bool { get }
}
```

### 3.2 各模块实现

#### 任务流模块 (TaskFlowModule)

```swift
struct TaskFlowModule: FlowModule {
    let flowType: FlowType = .task

    var showCheckbox: Bool { true }
    var showTime: Bool { false }
    var supportsSubtasks: Bool { true }
    var supportsDragReorder: Bool { false }
    var canComplete: Bool { true }

    func filterItems(_ items: [FlowItem]) -> [FlowItem] {
        items.filter { $0.flowType == .task }
    }

    func createItem(...) -> FlowItem {
        let item = FlowItem(...)
        // 任务流特殊逻辑
        return item
    }

    func toggleComplete(_ item: FlowItem) {
        item.status = item.isCompleted ? .pending : .completed
    }
}
```

#### 日程流模块 (ScheduleFlowModule)

```swift
struct ScheduleFlowModule: FlowModule {
    let flowType: FlowType = .schedule

    var showCheckbox: Bool { true }
    var showTime: Bool { true }
    var supportsSubtasks: Bool { false }
    var supportsDragReorder: Bool { false }
    var canComplete: Bool { true }

    // ...
}
```

#### 事件流模块 (EventFlowModule)

```swift
struct EventFlowModule: FlowModule {
    let flowType: FlowType = .event

    var showCheckbox: Bool { false }
    var showTime: Bool { true }
    var supportsSubtasks: Bool { false }
    var supportsDragReorder: Bool { false }
    var canComplete: Bool { false }  // 事件不可标记完成

    // ...
}
```

## 4. 实施步骤

### Phase 1：创建协议与基础结构

1. 创建 `FlowModule.swift` 协议文件
2. 创建 `Views/TaskFlow/`、`Views/ScheduleFlow/`、`Views/EventFlow/` 目录
3. 在各目录创建基础 View 文件（空壳）

### Phase 2：迁移任务流

1. 将 Task 相关的逻辑从 `TimelineListView.swift` 提取到 `TaskFlowView.swift`
2. 创建 `TaskItemView.swift`（特有逻辑）
3. 创建 `TaskEditorView.swift`（特有 UI）
4. 更新 `ContentView.swift` 使用 TaskFlowView

### Phase 3：迁移日程流

1. 同 Phase 2，将 Schedule 相关逻辑迁移
2. 创建 `ScheduleItemView.swift`（显示时间）
3. 创建 `ScheduleEditorView.swift`（时间选择器）

### Phase 4：迁移事件流

1. 同 Phase 2，将 Event 相关逻辑迁移
2. 创建 `EventItemView.swift`（里程碑样式）
3. 创建 `EventEditorView.swift`

### Phase 5：清理与优化

1. 删除旧的共用代码中的 FlowType 判断
2. 提取共用组件到 `Views/Shared/`
3. 统一命名规范

## 6. 后续优势

### 6.1 添加子任务（仅任务流）

在 TaskFlowModule 中实现：
```swift
var supportsSubtasks: Bool { true }
```

其他模块不受影响。

### 6.2 添加重复任务（仅任务流）

可在 TaskFlowModule 中添加：
```swift
var supportsRecurring: Bool { true }
```

### 6.3 添加里程碑（仅事件流）

可在 EventFlowModule 中添加：
```swift
var supportsMilestone: Bool { true }
```
